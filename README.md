## 安装

1. 下载本仓库并解压，或者解压上面的插件安装包。
2. 在 Chrome 打开 `chrome://extensions/`，开启开发者模式。
3. 选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的 `imagegrab-extension/`。
4. 在插件匹配的网站打开页面，点击右下角“获取图片”。
5. 在画廊中检查并勾选图片，点击“下载选中”。

本次成功的真实站点验证为淘宝；清单中配置的其他电商域名不等于已经逐站测试通过。

## 复现历史采集

历史成功不仅需要源码，还依赖已登录、允许本地 CDP 的 Chrome Profile，并且必须将该插件加载到同一个 Chrome 实例。登录资料不会放在本仓库，GitHub 上的代码本身不能复刻登录态。

1. 安装 Node.js 20 或更新版本。
2. 执行 `npm ci`，再执行 `npm test` 和 `npm run verify`。
3. 在目标 Chrome Profile 的 `chrome://extensions/` 中开启开发者模式，加载解压后的 `imagegrab-extension/`，然后打开淘宝并刷新页面。若由专用启动命令运行，则需在该次 Chrome 启动时传入 `--load-extension=<扩展目录>`；扩展不是淘宝账号的一部分，也不会自动出现在另一套 Profile 或未带该启动参数的实例中。
4. 确保该 Chrome 实例由用户自行按其本机安全策略开启 loopback CDP `127.0.0.1:9333`；不要把 CDP 端口暴露到公网。若同一 Profile 已被打开，不要启动第二个 Chrome 进程。
5. 在 `collection.config.json` 中检查关键词、页码、数量和输出目录，先运行 `npm run doctor`。
6. 医生检查通过后先运行 `npm run smoke`，确认少量真实下载落盘；再运行 `npm run collect` 执行完整批次。

运行器会拒绝登录/验证页面、检查浏览器下载历史、复制实际文件并验证 PNG 头；失败会在唯一的新运行目录中保留 `run.json`。不要把输出目录设到仓库源码、浏览器 Profile 或其他项目目录。

`npm test` 验证本地输入、文件处理、销量与商品关联、研究台和分页/滚动夹具，不会访问真实商品页面；`npm run doctor` 只验证旧课程 CDP 环境中的页面与插件按钮；`npm run smoke` 才是少量实时图片下载；`npm run collect` 才重跑图片批次。上述图片运行器依赖传统 HTTP CDP，不能直接代替普通 Chrome 内置远程调试的原生 WebSocket 接入步骤。2026-11-03 在原课程 Profile 中完成了 `doctor`、3 张 smoke 下载及 100 张真实批次验证；完整 300 张复跑没有完成。2026-11-04 的 1688 测试采集商品资料和图片 URL，没有下载图片文件。详情分别见两份真实验证记录；同机、同登录态实测不等于其他账户或全新电脑已验证。

## 本地归档检查

```powershell
node scripts/verify-snapshot.cjs
powershell -NoProfile -File scripts/verify-downloads.ps1 -CollectionRoot "你的采集目录"
```

`verify-snapshot.cjs` 检查插件源码和归档时的哈希是否一致，并检查结果清单的一致性。它不重新访问淘宝，不替代真实站点测试。

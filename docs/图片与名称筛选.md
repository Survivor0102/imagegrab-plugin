# 图片 / 名称筛选

当前版本：1.9.0。筛选功能自1.8.0提供，入口在选品研究台侧栏的“寻源工作区”→“图片 / 名称筛选”页签。它保留手动设置条件、分路搜索和人工读取候选的流程；同一区域另有“截图自动寻源”页签，可从截图识别后自动执行两路搜索。

## 操作顺序

1. 点击插件图标打开选品研究台，在侧栏打开“寻源工作区”，再选择“图片 / 名称筛选”。
2. 填写商品名称及品类，例如名称“亮亮照明 LED 筒灯”、品类“筒灯”。多个品类词任选其一；必需词需要全部出现。可填规格、品牌、型号及排除词。
3. 按需求选择“可接受其他品牌的相似替代品”或“同品牌 / 同型号候选”。后一种会把品牌、型号依据不足的记录留在待确认。
4. 有参考图片时上传 PNG、JPEG 或 WebP，可拖动框选商品本体，再点“使用框选区域”。点“移除参考图”可切回纯名称与文字条件筛选。
5. 点“打开1688图片搜索”或“打开1688名称搜索”。两路分别检索，不把全部筛选条件叠到图搜的“结果中搜索”里。自动上传使用平台原生文件入口；找不到入口会提示手动使用1688相机按钮。
6. 在1688完成搜索后，回筛选页点“刷新标签列表”，选择对应结果页和来源渠道，点“读取该页候选”。当前读取本页已加载的卡片；可以滚动加载更多后再读，也可以把图片搜索和名称搜索结果分批读入。按商品链接去重并保留来源。
7. 点“开始筛选”。有参考图片时，可先点“允许读取商品图片作本地比对”；授权由 Chrome 管理。同一扩展授权通常可保留，撤销权限或换 Profile 后需要重新处理。
8. 查看“优先候选 / 待确认 / 其余符合条件 / 已排除”。每件显示标题、价格、供应商、匹配依据和待核项，点“打开货源”查看原页面。
9. 勾选需要保留的货源，点“将勾选项加入商品池”，或“仅补全勾选项详情”。后者仅按选中的货源链接建立详情队列。已有运行中的榜单或详情任务会阻止启动；暂停、续采及详细进度在研究台查看。
10. 可导出本次候选 JSON。清空本次候选池会保留研究台已有商品、货源和规格资料。

## 数据与判断

- 候选及条件存于当前扩展的 `chrome.storage.local.imagegrabSourcingData`；正式研究档案在 `imagegrabResearchData`，只有明确导入才写入档案。
- 上传的参考图及裁剪结果存在本地。只有点击1688图片搜索才提交给平台；本地图片比对不调用外部 AI API。
- 候选图片保留网络链接；本地比对会读取图片像素，不等于下载图片文件到文件夹。已有“规格与图片”页面负责图片文件下载。
- 本地外观分综合差分哈希、灰度空间分布和颜色直方图。阈值为经验值；包装、背景、构图变化会影响结果，目前无法可靠判断同款、同型号或同一SKU。低分、读不到图片、指定规格缺失等情况保留待确认。
- 每次最多比对100个通过文字初筛的候选，每件最多两张图片。单张读取超时8秒，可停止。优先展示默认10件，最多50件，不自动将候选认定为同款。
- 名称匹配、同品牌文字命中都只作检索证据，具体规格、完整采购价和资质仍需在详情与供应商资料中核对。

## 实际验证

2026-11-05 使用已有授权的普通 Chrome，通过后台 CDP 操作，不启动另一套 Profile、不移动系统鼠标。新版加载后，原220个商品、220条货源和暂停中的220项详情任务保留。

实际1688纯图搜页面有60张商品卡片，当前模板通过卡片稳定ID和真实可见字段提取。使用“筒灯”及“电池、胶带、包装盒、识字、球泡”排除词，排除28件，剩32件。32件图片均读取并比较成功。整图及框选商品本体两次都没有达到外观分阈值，32件均列入待确认，说明本地图片算法在这一真实样本上的区分能力有限。没有通过降低阈值把它们写成已匹配。

移除参考图后，名称加品类筛选得到优先10件、其余符合条件22件、排除28件；“亮亮照明LED全塑嵌入式筒灯5W9W12W18W6500k白光吸顶装饰孔灯暗装”排在第一位。这是供人工比较的候选排序。

证据：`evidence/2026-11-05/sourcing-live-validation-1.8.0.json`（整图）、`sourcing-live-cropped-image-1.8.0.json`（框选）、`sourcing-live-name-only-1.8.0.json`（名称加品类）。

最终 `npm test`：45项通过，0失败，0跳过。自动检查包含真实加载扩展的合成1688页面：混合普通链接卡片和无链接卡片、两路去重、实际图片像素比对、裁剪保存和移除、只补选中一条货源、保护原档案、清空与重载持久化、原生图片框接收文件、原生中文搜索框提交。合成页面不等于真实1688上传、新开搜索页或详情补全已全部验证；本次真实站点未启动新的详情队列。

本次沿用已有浏览器流程中的“零结果先检查真实卡片结构”分支，适配代码和原始结果保留在插件项目。本地外观比对效果不足属于项目待改进项，尚不具备跨项目推广为可靠同款识别方法的证据。

2026-11-06继续对第一候选执行真实详情补全，得到8条SKU报价，12W白光和中性光各¥15；修复规格行图片读取后实际下载24张图片，全部可解码。两种12W共用同一张规格图，尚未依据用户自有条码唯一确认同款。实际流程、测试结果与自动化边界见[亮亮筒灯详情验证](2026-11-06-亮亮筒灯详情验证.md)。

只读检查已打开筛选页：`node scripts/verify-sourcing-live.cjs --label=current`。它读取普通Chrome的本机调试端口，输出当前页面与存储结果，不启动浏览器、采集或详情任务；需先取得该浏览器的授权与租约。

2026-11-06 对参考图中的“小桶装一次性黑色小皮筋”进行了图片 / 名称双路真实测试：图片搜索读取60条、名称搜索读取100条，按商品链接规范化去重后得到110条候选；文字初筛排除34条，76条进入图片比对，结果为优先1条、待确认75条。随后对优先候选和一条待确认候选执行详情补全，任务状态为完成。两件商品均未能从详情字段确认“35根/罐、20克/罐”，因此只能作为候选货源，不能写成已确认同款。完整过程、SKU、价格、发货地、媒体链接和边界见[小皮筋图片名称筛选实测](2026-11-06-小皮筋图片名称筛选实测.md)。

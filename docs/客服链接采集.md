# 详情补全中的客服链接（1.9.6）

第二阶段补全会读取当前商品页面中公开的卖家/前台卖家账号，保存对应的1688网页版客服入口。货源比较列表、商品档案中的货源卡片和“规格与图片”页均提供“联系客服”链接。

## 使用

1. 按原流程收集榜单或搜索结果中的货源链接。
2. 在“第二阶段 · 商品详情”选定要补全的范围，点击“批量补全详情”。
3. 旧记录如果已经有完整详情，需要勾选“重新采集已完成记录”。
4. 完成后点击对应货源旁的“联系客服”。需要保存到文件时，导出研究台CSV/JSON，或进入“规格与图片”下载该货源的CSV/JSON。

客服属于货源/供应商。同一家店铺的不同商品可能联系同一个账号；链接中的 `offerId` 提供本次咨询的商品上下文。不能按完整URL不同就认定它们属于不同店铺。

## 保存的数据

每条货源独立保存 `customerService`，包含 `url`、`loginId`、`memberId`、`offerId`、`sourceUrl`、`source`、`method`、`capturedAt` 及识别状态。详情快照同时保存当次识别结果。

链接按平台自身使用的网页版聊天路由生成，接收方参数为 `touid=cnalichn<卖家登录名>`，站点为 `siteid=cnalichn`，商品为 `offerId`。不保存买家登录数据或广告追踪参数。优先使用平台客服按钮实际选择的 `frontSellerMemberModel`，其次使用本商品的卖家字段；不从推荐商品或店铺名称推测客服账号。

页面中的客服按钮没有直接的 `href`。采集器读取页面自带初始化脚本中序列化的公开卖家对象，不执行网页脚本，也不依赖OCR。完整初始化内容含有未加引号的数字键，因此仅提取并JSON解析所需的小对象，避免把整段JavaScript误当成JSON。

未识别到当前商品账号时，记为 `not-found`，不影响其他规格资料采集；不生成猜测链接。曾成功保存的客服资料保留原采集时间，不伪装成本次重新获取。客服资料不作为商品“基础资料齐全”的必填条件。

研究台CSV附加客服链接、账号、会员ID、采集来源和时间；单货源规格CSV附加客服链接及账号。JSON保留完整对象。

## 验证

本次完整回归79/79通过，无跳过；包括前台卖家优先、不同店铺账号隔离、中文及特殊字符编码、当前商品ID校验、真实初始化数字键、推荐内容排除、队列保存、界面链接和导出。

真实普通Chrome中的对照及第二阶段运行结果见 `../evidence/2026-11-13/客服链接采集实测-1.9.6.md`。链接参数对照与实际聊天收发是不同的验证范围；本功能不自动发送消息。

# 1688 同名货源搜索修复记录

## 问题

选品研究台中的“在 1688 搜同名货源”按钮直接把商品名称拼进 URL。中文名称在 1688 搜索页中出现乱码，且 1688 当前页面的搜索按钮是页面脚本控制的 `.input-button`，不是标准 `<button>`。

## 修复

1. 先打开 1688 搜索页，不再把中文关键词直接作为初始 URL 参数。
2. 等待页面上的 `#alisearch-input` 或兼容的关键词输入框出现。
3. 使用原生 `HTMLInputElement.value` setter 写入完整中文，并派发 `input` 和 `change` 事件，让 1688 页面自己的状态同步。
4. 点击 1688 的 `.input-button` 搜索控件；普通表单页面则使用表单提交作为兼容路径。
5. 把注入页面的函数放在独立脚本中，保证 `chrome.scripting.executeScript` 序列化执行时不依赖后台 Service Worker 的辅助函数。

## 验证

- 独立生产函数测试：中文关键词保留、隐藏输入框不误选、无可用输入框时返回错误。
- 1688 控件夹具测试：识别 `.input-button`，派发输入事件并提交中文。
- 普通 Chrome 实测：通过研究台的真实按钮搜索“腋下吸汗贴止汗贴夏季腋窝吸汗垫腋毛防汗贴超薄隐形出汗止汗神器”。搜索框和页面标题保留完整中文，地址中的百分号编码由 1688 自己生成，结果记录见 `../evidence/2026-11-05/similar-search-live-1.6.2.json`。

本次验证确认的是中文关键词传递和搜索导航；不把搜索结果数量、结果相关性、平台登录状态或安全验证状态写成已全面验证。

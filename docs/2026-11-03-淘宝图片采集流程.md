# 2026-11-03 淘宝图片采集：实际成功流程

本文记录这次成功操作的先后顺序、使用方法和关键命令。历史原始工具调用另见 [实际命令摘录](2026-11-03-实际命令摘录.md)。下文的常规命令经过整理，环境路径改为变量；新整理的脚本与当时直接执行的命令会明确区分。

## 1. 目标和结果

用户要求尝试 5 个关键词，每个关键词收集 50 张，其中一个关键词收集 100 张。实际完成：运动鞋 100 张，女包、台灯、手机壳、双肩包各 50 张，共 300 个非空、文件头正确的 PNG。

本次采集单位是搜索结果页中的候选图片。没有逐个进入商品详情页收集所有图片，也没有建立图片与商品、销量或 SKU 的对应关系。

## 2. 当时用了什么

| 环节 | 实际方法 / 工具 |
| --- | --- |
| 执行命令 | `functions.exec` 调用 `tools.exec_command`，运行 PowerShell / Node.js |
| 浏览器交互 | `tools.mcp__node_repl__js`，在持久 Node REPL 中使用 Playwright |
| 浏览器连接 | Playwright `chromium.connectOverCDP('http://127.0.0.1:9333')` |
| 浏览器 | Chrome for Testing 154.0.8037.98 |
| 登录来源 | 原课程独立浏览器资料根内的 `Profile 2`；由用户正常完成淘宝登录 |
| 图片提取和下载 | 当前 ImageGrab 1.0.0 插件的真实按钮和下载逻辑 |
| 整理文件 | 读取 `chrome://downloads/` 的下载记录，使用 Node `fs.copyFile` |
| 结果校验 | PowerShell 调用 `.NET File.ReadAllBytes` 检查文件头；归档时补记 SHA-256 |

实际操作通过 CDP 控制浏览器页面，没有使用鼠标坐标抢占桌面。普通浏览器启动和用户登录属于有窗口阶段，不能把整个过程称为完全无界面的运行。

## 3. 先解决环境，再使用原登录来源

当时系统 Chrome 已升级至 155，而课程浏览器登记的版本为 154.0.8037.98，原启动入口拒绝版本不匹配。处理方式是下载匹配版本的 Chrome for Testing，不复制或重置已有登录资料。

### 3.1 下载并解压匹配的浏览器

当时先对官方 ZIP 做 HEAD 检查，再执行下载、解压。下面是相同操作的变量化写法：

```powershell
# 由操作者设置为项目内的工具目录，不要写入插件源码目录。
$browserTools = '填写项目内浏览器工具目录'
New-Item -ItemType Directory -Path $browserTools -Force | Out-Null
$zip = Join-Path $browserTools 'chrome-win64.zip'
$url = 'https://storage.googleapis.com/chrome-for-testing-public/154.0.8037.98/win64/chrome-win64.zip'
Invoke-WebRequest -Uri $url -Method Head -UseBasicParsing
Invoke-WebRequest -Uri $url -OutFile $zip -UseBasicParsing
Expand-Archive -LiteralPath $zip -DestinationPath $browserTools -Force
$chrome = Join-Path $browserTools 'chrome-win64/chrome.exe'
(Get-Item -LiteralPath $chrome).VersionInfo.ProductVersion
```

历史已使用的浏览器资料应与其写入版本匹配，不能拿此步骤直接回退其他已被更高版本写入的资料。

### 3.2 启动原课程 Profile 2

原记录使用 Node `child_process.spawn` 启动。普通启动尝试未能保留可连接进程；加入 `--disable-gpu` 和 `--no-sandbox` 后连接成功。检查发现该次启动没有加载插件，原操作随后结束了当时的专用浏览器进程，再使用同样的资料根、Profile 和端口，带插件参数重新启动。该历史重启动作见实际命令摘录，不应在复现时不经检查结束正在使用的浏览器。

以下是最终成功参数的整理写法，供与原命令核对。不是跨电脑通用启动器：先检查资料根是否正在使用，若已启动则复用，不要在同一资料根并行启动或清空它。

```javascript
const { spawn } = require('node:child_process');
const exe = process.env.CHROME_EXE;         // 匹配版本的 Chrome for Testing
const root = process.env.BROWSER_DATA_ROOT; // 已核对的原课程资料根
const ext = process.env.EXTENSION_DIR;      // imagegrab-extension 的绝对路径
if (!exe || !root || !ext) throw new Error('请先设置三个路径变量');
const args = [
  '--user-data-dir=' + root,
  '--profile-directory=Profile 2',
  '--remote-debugging-port=9333',
  '--remote-debugging-address=127.0.0.1',
  '--no-first-run', '--no-default-browser-check',
  '--disable-gpu', '--no-sandbox', '--start-minimized',
  '--load-extension=' + ext,
  '--disable-extensions-except=' + ext,
  'https://www.taobao.com/'
];
const child = spawn(exe, args, {
  detached: true, stdio: 'ignore', windowsHide: true
});
child.unref();
```

这些参数用于记录当时的兼容处理，尤其 `--no-sandbox` 不是插件常规安装的要求，也不建议作为日常浏览器配置。`--disable-extensions-except` 会影响该实例其他扩展，不能不加判断用于日常 Profile。

### 3.3 确认端点与实际资料身份

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:9333/json/version'
```

端点返回浏览器版本只证明 CDP 可连接；还应在 `chrome://version/` 核对实际资料路径确实是预期资料根内的 `Profile 2`。同名 Profile 在不同资料根下不是同一登录身份。

## 4. CDP 连接和登录后最小验证

历史操作在持久 Node REPL 中运行，以下变量由同一会话后续步骤复用。Playwright 是当时已经安装的运行时依赖；本次没有为采集重新安装任意版本的 Playwright。

```javascript
// 在 Node REPL / 支持顶层 await 的 JavaScript 环境执行。
// PLAYWRIGHT_MODULE_PATH 指向本机已有 playwright 包的 index.js。
var { createRequire } = await import('node:module');
var requirePw = createRequire(process.cwd() + '/imagegrab-session.cjs');
var pw3 = requirePw(process.env.PLAYWRIGHT_MODULE_PATH);
var browser2 = await pw3.chromium.connectOverCDP('http://127.0.0.1:9333');
var context2 = browser2.contexts()[0];
```

用户完成登录后，先验证真实商品详情页：

```javascript
var productPage = await context2.newPage();
await productPage.goto('https://item.taobao.com/item.htm?id=1088737131255', {
  waitUntil: 'domcontentloaded', timeout: 30000
});
await productPage.waitForTimeout(8000);
await productPage.getByRole('button', { name: '获取图片', exact: true }).click();
```

该次发现 46 个候选，其中包含淘宝 Logo。选第 2 张商品主图下载后，从下载记录找到临时文件，核实为 663,425 字节、PNG 文件头正确，随后才继续批次采集。

这一步证明了一张真实商品图片的提取和下载，并未证明 46 个候选全部有效。

## 5. 搜索关键词，通过插件建立画廊

以运动鞋第 1 页为例：

```javascript
var collectorPage = await context2.newPage();
await collectorPage.goto(
  'https://s.taobao.com/search?page=1&q=' + encodeURIComponent('运动鞋'),
  { waitUntil: 'domcontentloaded', timeout: 30000 }
);
await collectorPage.waitForTimeout(6500);
await collectorPage.getByRole('button', { name: '获取图片', exact: true }).click();
await collectorPage.waitForTimeout(3500);
var galleries = context2.pages().filter(p =>
  p.url().startsWith('chrome-extension://') && p.url().includes('gallery.html')
);
var galleryPage = galleries[galleries.length - 1];
```

插件 `content.js` 此时扫描 `img`、懒加载地址、`srcset` 和 CSS 背景图；按 URL 去重，并做基本尺寸和 URL 特征过滤，最多返回 500 个候选。`background.js` 把结果存入 `chrome.storage.local`，再打开画廊。

没有使用另一套直接请求图片 CDN 的批量下载程序替代插件。

## 6. 先滚动画廊，再筛选

画廊的图片元素有 `loading="lazy"`。最初约 30 张完成加载，继续等待也未让所有预览加载，因此改为滚动画廊触发懒加载。后续通用批次函数使用 80 次滚动：

```javascript
for (let i = 0; i < 80; i++) {
  await galleryPage.evaluate(() =>
    window.scrollBy(0, Math.max(window.innerHeight * 0.85, 600))
  );
  await galleryPage.waitForTimeout(160);
}
await galleryPage.waitForTimeout(1800);
var metas = await galleryPage.locator('img').evaluateAll(es =>
  es.map((e, i) => ({
    i, complete: e.complete, w: e.naturalWidth, h: e.naturalHeight,
    src: e.currentSrc || e.src
  }))
);
var usable = metas.filter(x =>
  x.complete && x.w >= 100 && x.h >= 100 &&
  !/600000000|\/tps\/|icon|logo|sprite|placeholder|loading|avatar|emoji|qr/i.test(x.src)
);
```

这是外部自动化增加的粗筛，不是插件已具备商品语义识别能力。该规则可能漏入无关图片，也可能误排有用图片；并未逐张人工确认。

## 7. 建立下载基线，点击插件下载

当时在第一次批量下载前建立已见路径集合，避免把此前下载误收进本批。下列整理代码保留原方法，只要求显式提供输出路径：

```javascript
var fsp2 = await import('node:fs/promises');
var collectionRoot = process.env.COLLECTION_ROOT;
if (!collectionRoot) throw new Error('请设置项目内的采集输出目录');
await fsp2.mkdir(collectionRoot, { recursive: true });
var downloadsPage = await context2.newPage();
await downloadsPage.goto('chrome://downloads/');
await downloadsPage.waitForTimeout(1000);
var getDownloadItems = async () => await downloadsPage.evaluate(() =>
  [...document.querySelector('downloads-manager')?.shadowRoot
    ?.querySelectorAll('downloads-item') || []].map(x => {
    const s = x.shadowRoot;
    const icon = s?.querySelector('#fileIcon');
    const link = s?.querySelector('#fileLink');
    const m = icon?.src?.match(/[?&]path=([^&]+)/);
    return {
      title: link?.getAttribute('title') || '',
      path: m ? decodeURIComponent(m[1]) : null,
      text: s?.innerText || ''
    };
  })
);
var baselineItems = await getDownloadItems();
var seenDownloadPaths = new Set(baselineItems.map(x => x.path).filter(Boolean));

var chosen = usable.slice(0, 50);
for (const x of chosen) {
  await galleryPage.locator('input[type=checkbox]').nth(x.i).check();
}
await galleryPage.getByRole('button', { name: '下载选中' }).click();
```

插件 `gallery.js` 串行执行：请求图片 → `createImageBitmap` 解码 → canvas 按原尺寸绘制 → `toBlob('image/png')` → `chrome.downloads.download`。失败时通过 `DOWNLOAD_ORIGINAL` 请求后台下载原 URL。

等待画廊显示“处理完成”之后仍需核对实际文件，不能把“已启动下载”直接当成落盘完成。

## 8. 下载列表也要滚动，找到真实落盘位置

本次 Playwright 接管下载后，文件实际落入它的运行时临时目录，文件名为 UUID，不是系统“下载”目录中的 `商品图_001.png`。

从 `chrome://downloads/` 中 `downloads-manager`、`downloads-item` 的 Shadow DOM 读取 `#fileIcon` 的 `chrome://fileicon/?path=...`，解码取得真实路径。该方法依赖此版本 Chrome 的内部页面结构，不保证其他版本不变。

第一次只读到 6 项，继续等待仍未补齐。滚动下载管理页的 `#mainContainer` 后才加载出完整记录；首次批量下载对应 52 项，包含此前 2 项和新增 50 项。

```javascript
for (let i = 0; i < 35; i++) {
  await downloadsPage.evaluate(() => {
    const m = document.querySelector('downloads-manager');
    const c = m?.shadowRoot?.querySelector('#mainContainer');
    if (c) c.scrollTop = c.scrollHeight;
  });
  await downloadsPage.waitForTimeout(120);
}
var all = await getDownloadItems();
var fresh = all.filter(x => x.path && !seenDownloadPaths.has(x.path));
```

## 9. 复制到关键词目录并重命名

```javascript
var dirName = '运动鞋';
var outDir = collectionRoot + '/' + dirName;
var startNo = 1;
await fsp2.mkdir(outDir, { recursive: true });
var saved = 0;
for (const item of fresh) {
  await fsp2.copyFile(item.path,
    outDir + '/' + dirName + '_' + String(startNo + saved).padStart(3, '0') + '.png');
  seenDownloadPaths.add(item.path);
  saved++;
}
```

这是将历史整理逻辑写成可读示例；原始函数会忽略复制失败，最后按保存数核对。文件编号来自下载列表顺序，不能把编号当作商品排名、画廊原编号或可靠的来源关联。

共享浏览器可能同时产生其他下载，历史方法未按扩展下载 ID 做精确归属隔离。应在独占测试会话使用，不能不加修改用于有其他并发下载的环境。

## 10. 建立通用批次函数，补齐五个关键词

运动鞋第 1 页已用前面的分步操作保存 50 张。随后建立 `collectKeywordBatch`，完整原函数保存在 [历史函数文件](../scripts/historical/collect-keyword-batch.js)。

在持久 Node REPL 中初始化前述变量后，可将该函数文件内容粘贴进同一会话。它不包含浏览器启动、登录或变量初始化，直接 `node collect-keyword-batch.js` 不会完成采集。

之后当时依次执行的是：

```javascript
await collectKeywordBatch('运动鞋', 2, 50, '运动鞋', 51);
await collectKeywordBatch('女包', 1, 50, '女包', 1);
await collectKeywordBatch('台灯', 1, 50, '台灯', 1); // 实际仅保存 46 张
await collectKeywordBatch('台灯', 2, 4, '台灯', 47); // 补到 50 张
await collectKeywordBatch('手机壳', 1, 50, '手机壳', 1);
await collectKeywordBatch('双肩包', 1, 50, '双肩包', 1);
```

各批真实候选数、粗筛数和保存数见 [验证结果](验证结果与限制.md)，机器可读返回值见 `evidence/2026-11-03/batch-results.json`。

## 11. 最后检查磁盘中的文件

当时先使用 `Get-Content -Encoding Byte` 检查文件头，但该参数在所用 PowerShell 中报错。随后改为 `.NET File.ReadAllBytes` 重验，不能把第一次检查报错忽略后称为通过。

核心检查方法：

```powershell
$bytes = [System.IO.File]::ReadAllBytes($file.FullName)
if ($bytes.Length -lt 8 -or
    (($bytes[0..7] -join '-') -ne '137-80-78-71-13-10-26-10')) {
    # 此文件不能通过 PNG 文件头检查
}
```

本仓库新增了相同检查方法的只读脚本，可明确指定采集根目录：

```powershell
powershell -NoProfile -File scripts/verify-downloads.ps1 -CollectionRoot '实际采集目录'
node scripts/verify-snapshot.cjs
```

归档时重新读取了现存的 300 个图片文件，复核数量、非空状态和 PNG 文件头，并补记每个文件的 SHA-256。记录见 `evidence/2026-11-03/file-verification.json` 和 `image-file-manifest.json`。这不是再次联网采集，也不是逐张视觉核验。

## 12. 哪些由插件完成，哪些由外部自动化完成

| 插件完成 | 外部自动化完成 |
| --- | --- |
| 当前页图片地址扫描和基本过滤 | 浏览器启动、CDP 连接、关键词导航与跨页 |
| 画廊预览、勾选及反选界面 | 滚动画廊触发懒加载、额外 URL 特征粗筛 |
| 转 PNG、创建浏览器下载请求、原图兜底 | 读取下载管理页、复制文件、按关键词命名 |
| 单次画廊内按 URL 去重 | 数量与文件头校验、整理采集记录 |

本次未修改插件功能。销量、逐商品关联、多口味 / SKU 图片对应、内容去重和高清原图识别均未在本次完成，不应从这份成功下载流程推断为现成功能。

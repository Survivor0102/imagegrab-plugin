# 2026-11-04 普通 Chrome 接入与榜单验证

这份步骤适用于本次已成功连接的普通 Chrome 内置远程调试模式。它不是重启浏览器的启动命令。现有淘宝图片批次运行器仍面向传统HTTP CDP9333，不把那套运行器的成功直接移用到这里。

## 准备与身份

1. 保持用户已经登录并可正常访问1688的普通Chrome打开。
2. 在 chrome://inspect/#remote-debugging 启用该实例的远程调试，出现远程调试授权时允许本次本地连接。不要启动另一个使用同一资料根的Chrome。
3. 读取普通Chrome资料根中的 DevToolsActivePort。默认位置为 %LOCALAPPDATA%/Google/Chrome/User Data/DevToolsActivePort；首行是本地端口，次行是本次随机的浏览器WebSocket路径。
4. 从Chrome版本页核对实际Profile。本次是Default，Chrome155.0.8059.86，并不是课程Profile 2。
5. 多任务环境先取得这个实际资料源的租约。项目不包含用户的浏览器资料、账号或租约token。

本次 /json/version 和 /json/list 返回404；Playwright连接超时。原生WebSocket成功，因此不必为了HTTP端点404而重启或换Profile。

## 连接

Node.js 22+，本次实际使用24.14.1。进入仓库后：

~~~powershell
node scripts/ordinary-chrome-cdp.cjs --probe
~~~

探测只发 Browser.getVersion，返回后断开连接，浏览器继续运行。

交互连接：

~~~powershell
node scripts/ordinary-chrome-cdp.cjs
~~~

也可以把实际DevToolsActivePort文件路径作为第一个参数。每行输入一个标准CDP JSON命令，例如：

~~~json
{"id":1,"method":"Browser.getVersion"}
{"id":2,"method":"Target.getTargets"}
~~~

客户端会筛去无关页面的target元数据；只在已确认的1688榜单标签和ImageGrab研究台上继续操作。targetId、sessionId和WebSocket路径每次可能不同，不能照抄历史值。

## 本次实际操作顺序

1. Target.attachToTarget 连接目标页面，使用 flatten:true，保存返回的sessionId。
2. Extensions.loadUnpacked 加载仓库下 imagegrab-extension 的绝对路径。Chrome返回扩展ID。扩展只需安装一次，修改源码后重载并刷新任务标签；不必每次重新安装。
3. 本次从1688首页已有的“全网销量榜”链接进入测试标签，目标页即实测记录中的工艺品榜单。没有构造隐藏数据接口。
4. 版本更新时，在已确认的 chrome://extensions/ 页会话中调用：

~~~javascript
new Promise(resolve => chrome.developerPrivate.reload(extensionId, {}, () =>
  resolve({ok: !chrome.runtime.lastError, error: chrome.runtime.lastError?.message})))
~~~

5. 对任务榜单发送 Page.reload，等待20个 .cgf-product-card 和扩展按钮出现。
6. 通过 Runtime.evaluate 点击实际扩展按钮：

~~~javascript
document.getElementById('imagegrab-research-button').click()
~~~

这次单页采集实际进入扩展后台，打开研究台并导入20条。研究台导入后会消费移除 imagegrabResearchCapture，因此该临时键为空不表示导入失败，应同时核对 imagegrabResearchData 的 products 和 offers。

7. 更新到1.3.1后，再通过页面中的真实按钮执行自动采集：

~~~javascript
document.getElementById('imagegrab-research-auto-button').click()
~~~

8. 在扩展研究台会话中读取真实存储：

~~~javascript
chrome.storage.local.get(['imagegrabResearchAutoJob','imagegrabResearchData'])
~~~

本次job保存20条、pageCount为1、running为false，结束原因“列表滚动后未检测到新增商品（已停止）”。在榜单页独立读取每张卡片标题、价格、月销量，与job逐条比较，20条一致。

9. 需要手动停止时点击：

~~~javascript
document.getElementById('imagegrab-research-stop-button').click()
~~~

10. 输入 disconnect 只断开CDP；释放本会话租约，保留普通Chrome和用户页面。客户端拒绝 Browser.close。

## 复核代码和安装包

~~~powershell
npm test
node scripts/update-source-snapshot.cjs --date=2026-11-04
npm run verify
powershell -NoProfile -File scripts/build-extension.ps1
~~~

当前版本1.3.1，安装包位于 dist/imagegrab-extension-1.3.1.zip。打包脚本拒绝覆盖已有同名包，源码快照拒绝用同一版本覆盖不同内容。旧版本作为历史保留。

自动化夹具覆盖3批列表追加，但本次真实榜单仅返回20条且滚动后没有新增；目标Top1000还需要找到确切页面再验证。不要将程序上限1000写成已采集1000。

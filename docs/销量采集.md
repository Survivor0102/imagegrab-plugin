# 销量采集（ImageGrab 1.1.1）

## 当前行为

- 只读页面当前可见的文字，不发起隐藏接口请求，也不推断后台交易数据。
- 保留页面原始口径，例如“月销 1.2万+”“已售 328 件”“2.4万人已付款”；不同口径不换算、不合并。
- 搜索结果页仅当包含图片、商品链接和销量文字的共同 DOM 容器能够被识别时才关联；商品详情页尝试读取标题、当前链接和可见销量文字。
- 关联失败时画廊显示“页面未识别到销量”，不把别的商品或整页数字贴到图片上。
- 一个商品卡片中的图片共享该商品上下文；这不代表识别了 SKU，也不代表该图对应某个口味或规格。

## 验证状态

- 本地单元测试覆盖常见销量标签、带“万”的数字以及无标签数字不误识别。
- 使用独立 headless Chrome 对仿真的淘宝搜索页和详情页 DOM 运行了插件实际扫描脚本，并验证画廊显示；覆盖不同销量口径、推荐区隔离、相同图片 URL 多商品冲突处理。测试命令：`npm test`。
- 2026-11-03 在已登录的课程 Profile 2 中完成真实淘宝搜索页验证：1.1.0 首次测试识别失败，定位到淘宝搜索卡片使用 `click.simba.taobao.com/cc_im` / `mclick.simba.taobao.com/cc_im` 跟踪链接。1.1.1 纳入该类卡片链接并从独立标题节点读取标题；最终复测 72 张候选图中 69 张识别到商品标题和页面销量原文、68 张识别到商品链接，未识别项没有误用整页销量。
- 商品详情页尝试进入搜索结果中的一个商品后，淘宝显示“访问异常提示”，阻止正常查看完整详情。已停止继续探测；因此详情页销量提取仍只通过仿真 DOM 测试，真实详情页未验证。
- 浏览器实测记录：`evidence/2026-11-03/live-sales-validation.md`。验证前发生扩展重载并确认未打包扩展被停用；开启开发者模式后确认扩展重新启用。测试期间详情页显示平台访问异常提示，因此没有进行规避访问。
- 不声称覆盖淘宝所有页面版本、天猫、京东或拼多多。详情页/搜索页匹配逻辑目前是启发式规则。
- 仍需在允许正常访问的商品详情页复测详情销量提取；搜索页验证结果不能代替详情页验证。不绕过站点访问限制。

## 页面中的口径限制

页面显示的销量标签只是页面向访客展示的文字，可能有平台自己的统计窗口与取整规则。插件保存的是识别到的原文，不把它解释为精确成交数、库存数或某段期间的全部订单数。

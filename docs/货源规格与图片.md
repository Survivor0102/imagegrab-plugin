# 货源规格与图片

版本：1.6.0（界面最初在1.5.0加入）。

## 进入方式

先打开1688商品详情页，页面左下角显示“加入选品研究”。点击后，切到打开的研究台标签页。1.5.3补齐此按钮的悬浮样式加载；从旧版更新时，在 `chrome://extensions/` 重载ImageGrab，再刷新商品页。

2026-11-04已在普通Chrome实际重载至1.5.3，刷新商品801178335924后核对按钮为fixed定位、位于视口内且可点击，原有20条商品及20条货源保留。证据：`evidence/2026-11-04/research-entry-live-1.5.3.json`。此检查未再次采集商品，避免覆盖已保存的多选项规格。

在研究台左侧打开“货源比较”，每条货源的“打开货源”旁边有“规格与图片”。点击后进入该条货源的二级界面；商品档案里的货源卡也有相同入口。顶部“返回货源比较”回到列表。

页面包括供应商、发货地、采集时间、报价说明、规格售价库存表、每行对应选项图，以及分组展示的主图、规格选项图和详情图。共享颜色图标记“共享选项图”；缺图显示未采到，不用商品主图冒充该规格图。

## 保存和下载

- 采集详情后，规格、报价、库存和图片URL按每条货源保存于浏览器本地存储。不同店铺/货源分别保存，即便被用户并入同一商品，也不共用一份报价表。
- 旧版商品级详情，仅在来源URL与该货源URL匹配时迁移；其他货源不会借用该规格。没有详情的货源显示待采集说明。
- “下载规格表CSV”：一行一个规格，包含供应商、货源链接、发货地、规格、选项、价格说明、售价、库存、图片URL、关联类型及采集时间。
- “下载资料JSON”：该条货源的完整结构化资料，并包含截至导出时的图片下载记录。需要最终下载结果时，等图片完成后再导出。
- “下载全部图片”和每张图下的“下载图片”：调用浏览器下载API，保存实际图片文件到浏览器下载目录下的 `ImageGrab/货源-<货源ID>/images/`。不强改文件格式；扩展名按资源URL保留。
- 图片任务逐项显示进行中、完成或失败，结果保存在浏览器本地。下载失败不会显示成完成；重新打开页面可核对未完成下载的状态。
- CSV与JSON文件使用浏览器的默认下载目录；重名文件由浏览器保留为新副本。

## 实测

2026-11-04，在已有普通Chrome中重载实际扩展，通过真实“规格与图片”链接进入木珠货源二级界面，正确显示15行规格、报价、库存和原木色共享图。实际点击下载规格表、资料JSON及全部图片。

18个媒体URL全部下载完成；逐文件检查非空、Pillow解码、尺寸与SHA-256，共3,043,043字节，实际格式JPEG/WEBP。CSV为表头加15行，最终JSON含15个规格和18条图片下载记录。这里18是不同URL数，其中有同一照片的不同版本，不等于18张不同照片。

本机下载样本整理于 `output/2026-11-04-天台乐铭工艺品厂-规格与图片/`，包含实际图片、CSV、JSON和文件清单；该目录属于本地业务输出，不纳入Git。浏览器原下载文件保留，下载记录里的文件夹入口仍有效。

证据：`evidence/2026-11-04/offer-page-live-1.5.0.json` 和真实浏览器截图 `货源规格与图片_真实浏览器_1.5.0.jpg`。

本地19项测试通过，含真实历史样本的二级页展示、URL匹配迁移、两家供应商隔离、空资料、CSV/JSON导出、共享图片标识和下载完成/失败状态。模拟测试中的下载API为测试替身；上述18个真实文件另由已安装扩展下载，并做文件校验。

## 当前范围

1.6.0已将逐件切换规格的采集流程整合到研究台“批量补全详情”。具体范围选择、进度和续采见[两阶段采集](两阶段采集.md)。下文普通单次点击和历史批次的记录仍指各自当时版本。

普通单次点击保存当前已选选项下的规格；本件只有一个原木色选项，15个尺寸均已保存。2026-11-04后续通过真实扩展的浏览器批次函数逐项切换其余19件商品的选项，并展开售罄行，完成762行规格报价及579个图片文件；见[完整流程与边界](2026-11-04-其余19件商品批次下载.md)。这是实际批次流程，不代表二级页已有“一键遍历所有选项”按钮，也尚未验证食品口味模板。链接预览需要网络；下载文件可离线查看，下载资料不会自动使插件预览改用本地文件。

新增界面和下载功能的实现、测试、证据和本地输出均归入原插件项目；项目外仅有浏览器按默认设置生成的原始下载文件，本次保留以维持浏览器下载记录的可用性。

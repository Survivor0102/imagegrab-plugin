## 操作流程

1. 打开“截图自动寻源”，选择商品详情、商品管理或零售页面的截图。
2. OCR 在本机运行，页面显示识别原文和识别字段。低置信度时保留原文但留空名称等搜索条件。可以框选商品主体后直接只做图搜，或手动填入可靠的简短名称。条码、SKU、SPU仅作为来源记录，不当作1688型号。
3. 点击“自动搜索并筛选”。插件打开1688原生图片搜索、上传并点击“搜索图片”；有名称时再独立提交名称搜索。验证各自结果页生效且列表稳定后，才读取当时已加载的卡片。
4. 去重后调用原有的文字条件与可选图片像素比对，将结果分为优先候选、待确认、其余符合条件和排除项。
5. 在“截图自动寻源”本页下方查看结果。若显示未评分，点击“比对候选图片并评分”，首次需要允许插件读取阿里图片域名。比对完成后查看各分组，人工勾选后才可加入商品池或启动详情补全。
6. 刷新会恢复当前自动任务的参考图、候选、已有评分与勾选状态；切换“图片 / 名称筛选”才会看到手动候选池。自动结果不会写入手动池。

## 自动化边界

- OCR 引擎、语言模型和 WASM 核心都随扩展本地提供；截图文字识别不请求外部 OCR 服务。
- 点击启动后，商品图片会提交到1688原生图片搜索，识别出的商品名称会作为独立搜索词提交给1688。
- 自动读取的是各搜索页当时已加载的候选卡片，不会代替用户滚动、遍历所有分页或自动打开每件详情。
- 图片像素比较需要用户另行授予可选的1688图片域名读取权限；未授权时仍可按名称、品类和规格文字筛选。
- 只有图片而没有可靠名称、也未开启图片比对时，候选全部保留在“待确认”，界面显示“未评分”，不会把内部占位的0显示成已执行比对的分数。
- 登录、安全验证、平台页面变化或上传入口不可用时暂停并保留已读取候选，不尝试绕过验证。
- 候选排序不是同款概率。插件不自动确认同款、不自动导入商品池，也不自动补全详情。

## 页签设计

两种流程服务于同一个“寻源”任务：手动页签适合分别调整搜索条件、控制读取页面和逐步筛选；截图页签减少手工录入与搜索提交操作。两者只复用卡片渲染与评分算法，各自控制候选状态和存储。自动结果始终显示在截图页签，手动结果始终显示在手动页签。

本地像素算法比较缩小图片的边缘、明暗布局和颜色分布，不理解猫脸、夹型或具体SKU。当前实测中的人工最接近基线商品外观分56，仍在待确认；另外两条基线为68、67，也在待确认。高于70的四条只表示该算法的外观线索命中，不能替代人工看图。本轮解决的是结果归属、持久化和真实评分执行，未证明排序优于人工。

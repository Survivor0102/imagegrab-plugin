## 原来哪些说法不应继续沿用

1. 早期未登录搜索得到 5 张公共资源，不能作为商品搜索采集成功证据。
2. 更早淘宝首页的 53 个候选，不能证明某个商品的 53 张图片全部下载成功。
3. 画廊最初只有约 30 张加载，不代表后面的候选都损坏；需要滚动画廊触发懒加载。
4. 下载管理页最初只显示少量条目，不代表只有这些文件下载成功；需要滚动加载下载列表，再核对文件。
5. 当前批次的 300 张来自搜索结果页，不是逐个进入商品详情页收集完整图集。

## 当前版本的能力边界

- 内容脚本按整页资源扫描，不识别“一个商品”的边界。
- 插件仅按完整 URL 去重，不做图片内容去重；跨页和跨关键词也未统一去重。
- 外部自动化额外使用 URL 特征粗筛，可能误排商品图或漏入公共资源。
- 未导出逐文件的原图 URL、商品 ID、商品链接、销量或 SKU 关联；现有记录无法完整倒推这些关系。
- 下载重命名顺序来自浏览器下载列表，不保证对应搜索排名或画廊编号。
- `DOWNLOAD_ORIGINAL` 兜底直接下载原 URL，即使文件名为 `.png`，内容编码也不保证为 PNG。
- 本次未对当前版本进行多口味 / SKU 采集验证。相关需求仍是后续扩展，不列为已完成功能。
- 历史批次函数关闭所有画廊页、捕获新下载记录，适用于当时独占的测试会话；共享浏览器同时有其他下载时不应原样重放。

归档时新增的 SHA-256 只用于核对文件身份，不表示当次做过图片内容去重、商品识别或人工复核。

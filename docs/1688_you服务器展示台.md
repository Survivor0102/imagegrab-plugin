# 1688_you 网站展示台

版本：ImageGrab 1.11.3。网站入口：`http://47.94.215.192:8000/static/frontend/goods/ImageGrabYou`。

## 按原产品查看候选

网站默认进入“寻源目标”：左侧为用于搜索的原产品、关键词和目标规格，右侧为该目标的候选货源，不把每个供应商当成新的原产品。一个目标可以保留多次搜索条件，查看候选时可分别筛“同品牌 / 不同品牌 / 品牌待核”和“包含目标规格 / 规格冲突 / 规格待核”。展开候选可核对参数、SKU、报价、图片、发货地和客服。

品牌关系与规格关系相互独立；标题提到目标品牌不足以确认同品牌。“亮亮”和“亮亮照明”这种可能的简称差异标为待核，不直接算不同品牌。规格标签仅比较已经提供的条件；未提供的开孔、电压等不推断一致，也不表示已确认可直接替代。

“榜单商品”继续按榜单范围查看；“待归属”保留没有搜索关联证据的历史档案；“全部档案”仍能查原商品和货源。没有新增需要手动填写的需求卡流程。

本轮按保存的搜索条件恢复3份条件、6条关联；根据用户确认，将两次亮亮照明查询挂到同一目标下。现在共有2个寻源目标：亮亮4个候选、皮筋2个候选，另有1个球泡历史档案待归属。没有按标题相似自动合并其他商品。

## 权限和数据库

新增的是商品登记助手网站的导航Tab，位于原“1688”旁边。与原1688一样，仅管理员可见。前端复用 `user.isAdmin()`，后端复用 `is_admin()`；隐藏导航之外，GET/POST接口也会核验管理员身份。普通账号不可读写，不是所有登录者可见。

继续使用现有MySQL `goods` 数据库，累计使用五张独立表：

| 表名 | 保存内容 |
| --- | --- |
| `imagegrab_you_product` | 商品档案、品牌、类目、来源与榜单标签、图片链接、认证记录及原始字段 |
| `imagegrab_you_offer` | 对应供应商、价格、起订量、销量文字、发货地、客服入口、规格与图片和详情资料 |
| `imagegrab_you_job` | 最近主动同步的采集任务状态快照 |
| `imagegrab_you_request` | 原产品的搜索条件、输入图预览和明确的历史查询关系 |
| `imagegrab_you_candidate` | 原产品的全部候选及判断依据，可关联已入池货源；未入池时保留独立采集记录 |

新表与网站原1688业务表隔离。所有管理员共享展示台数据，不新增“仅上传者可见”的限制。通过客户端稳定ID隔离不同设备的本地ID；同一客户端重复同步更新原记录。同一商品下的1688链接按offer编号规范化，避免查询参数变化产生重复货源。

## 怎么把插件资料同步到网站

1. 在当前使用ImageGrab的同一个Chrome、同一个Profile里，打开 `chrome://extensions/`，对原ImageGrab扩展点击重新加载。解压缩扩展的来源目录应是当前维护目录 `C:\Users\ASUS\Desktop\插件\imagegrab-extension`；若不是该目录，先核对现有安装来源，避免卸载后丢失本地资料。
2. 刷新插件研究台，在扩展管理页核对版本为 **1.11.3**。
3. 在同一个浏览器里打开上述网站，登录网站管理员账号。服务器SSH的root身份与网站管理员登录是两回事。
4. 在研究台点击 **“同步到 1688_you”**，选择当前登录的网站地址。也可点击对话框里的打开网站按钮。
5. 点击开始同步。第一次允许所选服务器的扩展访问权限，随后等待批次完成，保持研究台与网站标签页打开。
6. 到网站的 **1688_you** Tab点击刷新，默认查看“寻源目标”；也可切换榜单和全部档案。

支持当前服务器IP地址及 `https://shopserve.xin`、`https://www.shopserve.xin`。登录态按地址区分，请选择与已登录标签一致的地址。

同步范围是本Profile商品池中的全部商品、关联货源和认证记录、当前详情任务快照，以及三个独立寻源池中能够恢复搜索条件的候选。独立候选不会自动变成正式货源；只有明确加入商品池后，网站才把它关联为已入池货源。

1.11.0起，加入商品池时一并保存当次搜索输入和候选关联，后续同步将其上传。1.11.1起，独立寻源池中的候选也会上传为“未入池候选”，不再因为尚未加入商品池而从原产品视图消失。页面同时显示已读取数量、优先候选、待核对、已排除、已入池及默认前20条待核/补全队列；待核对不等于匹配成功，网站不执行采集。更换候选池、清空临时结果不会抹掉已加入档案的原产品。JSON备份也包含关联；旧JSON没有关联时保留为历史格式。输入图同步时只缩小网站预览，本地原图保留；历史原图缺失会明确显示，不借用候选图片。

## 同步后的行为

- 这是用户主动执行的本地到服务器增量同步，不是后台持续推送。再次点击会更新原记录；本地删除的商品不会自动从网站删除。
- 本地档案仍保留。网络中断时已成功批次保留，再次点击同步可重试，不需要清空网站数据。
- 规格高清图、主图和详情图保存的是原采集链接，没有自动将图片文件下载到服务器。原链接失效仍需重采或另行下载。
- 寻源输入图是例外：新保存的输入会同步一份不超过640像素的预览；它不替代原图或详情图片下载。
- 认证记录保留原状态，存在认证字段不表示已经核验。候选报价、销量、供应商可从本卡已保存文本恢复并注明来源；详情缺失的发货地显示“待详情补全”，认证未采集则明确注明。
- 插件在已登录网站的页面环境里执行同源请求，复用网站登录；不要求填写或保存网站密码，不把网站访问令牌返回插件。
- 网站展示最近同步时的任务状态，不在服务器继续执行浏览器采集。榜单采集、逐页补全、人工核对仍在插件里完成。
- 已入池货源同步时会携带候选阶段、评分和前20顺序；网站端详情补全与候选阶段分类因此分开显示，但不会把已补全资料自动解释为匹配成功。

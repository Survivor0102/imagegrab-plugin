# 1688 自动分页真实站点冒烟记录

- 页面实际重定向至 `https://login.taobao.com/`，未显示商品卡片、分页控件或扩展操作按钮。

- 因此本次没有验证真实 1688 分页控件识别、真实商品字段准确率或连续翻页效果。

## 验证边界

自动分页算法已通过本地浏览器夹具测试：模拟 3 页、重复商品去重、末页停止，13 项项目自动化测试全通过。真实站点测试需要可用且经 Profile 租约登记的已登录浏览器。首轮把另一套 `test1` 的租约误判为课程 Profile 占用；该判断已在后续核对中纠正，详见下节。

真实 Top1000 榜单页尚待在用户指定、已登录的 Profile 中小范围验证后，才能确认兼容性和是否可完整采集。

## 课程 Profile 后续复测

- 按用户指定显式解析并选择 `course-legacy`（旧桥接根 `browser-bridge-user-data` 下的 Profile 2），没有使用 `test1`。
- 首轮排查曾把 `test1` 的租约误当成课程 Profile 占用。实时登记显示两者的专用资料根不同；课程 `course-legacy` 租约空闲。该判断已纠正，没有触碰 `test1` 的租约。
- 首轮直接调用受管理 `spawn` 启动器时，Chrome 154 以退出码 3 退出。随后改用既有桥接的 Playwright 持久化上下文启动方式，并显式绑定课程 Chrome for Testing 154.0.8037.98、课程资料根、`Profile 2` 和最小化窗口参数；启动成功。
- 登记器实测确认进程路径、资料根、Profile、版本及 `127.0.0.1:9333` CDP 端点全部匹配。浏览器打开 `https://www.1688.com/` 后出现滑块验证页；用户手动尝试后页面返回 `error:870BR3`。用户报告另一个已开启浏览器可正常访问。没有继续重试、绕过验证或开始榜单分页/字段采集。
- 自动化窗口由 Playwright 持久化上下文启动，与用户所说的另一个正常浏览器存在运行时差异；这可能影响验证码判断，但根因未证实。公开资料未找到 `870BR3` 的具体释义，不将其归因于账号异常或 Profile 损坏。
- 当前结论：课程浏览器启动链路已恢复，但该自动化窗口无法通过站点验证；真实榜单分页和字段准确率仍未验证。后续应先按用户确认的正常浏览器身份和租约核对是否能安全接入，不在此自动化窗口重复尝试。

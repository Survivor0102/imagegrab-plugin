## 实际流程与命令

1. 复用已经运行的普通Chrome，登记浏览器工作区租约。沿用 `DevToolsActivePort` 原生WebSocket接法，不启动另一套Profile。
2. `node scripts/ordinary-chrome-cdp.cjs` 建立会话；在本次新建的后台商品标签使用 `Page.navigate` 打开上述链接，以 `Runtime.evaluate` 检查商品区DOM。
3. 修复旧详情采集：通用h1误取店铺名、全部商品链接混入推荐、供应商url覆盖商品url。详情长图位于开放Shadow DOM，改为限定详情区域递归读取。
4. 在后台扩展管理页使用 `chrome.developerPrivate.reload(extensionId, {}, callback)` 重载扩展；`Page.reload` 刷新本次商品页。后台滚到 `#description` 等待长图渲染。刷新后自定义元素从v-detail-j变成v-detail-q，递归Shadow Root仍有效。
5. 实际点击 `#imagegrab-research-button`；真实内容脚本发送OPEN_RESEARCH，后台打开研究台自动导入。通过研究台 `chrome.storage.local.get('imagegrabResearchData')` 回读存储。
6. 以规范化商品URL匹配已有档案；采前采后商品数20、货源数20，本件仅1条货源。重复采集保持同一档案，销量来源记录保持3条。
7. 将实际存储样本与 `scripts/detail-dom-audit.cjs` 独立读取的真实DOM比较：标题、供应商、价格、全部参数、15项SKU报价库存、主图和详情图全部匹配。
8. `npm test`：18项本地测试通过。`npm run snapshot -- --date=2026-11-04`、`npm run verify`、`pwsh -File scripts/build-extension.ps1` 用于版本快照、完整性核验和打包。

浏览器操作通过后台CDP完成；结束保留商品与研究台，关闭本次辅助管理标签、断开客户端并释放租约。
